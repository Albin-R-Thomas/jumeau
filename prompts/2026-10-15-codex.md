# Cache policy update

User request: replace the 122-minute weather cache with about 15 minutes and allow older cached responses when the provider is unavailable or quota is reached.

Implementation decisions: use 900-second freshness plus a separate backup retained for 24 hours from the last successful fetch. This retention bound is a reasonable implementation choice because no maximum stale age was specified. Fresh and backup reads do not renew TTL. Provider failures/timeouts and local/provider quota errors permit fallback; authentication/not-found and database/Redis outages retain their existing error handling. Stale successes preserve the observation timestamp and record cache history. Versioned keys avoid treating old 122-minute entries as fresh. Compose pins 900 seconds so private legacy env values cannot override the updated requirement. No private env files were inspected or changed.
